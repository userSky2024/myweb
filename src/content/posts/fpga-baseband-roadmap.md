我对"看得见的结果"一直没什么执念。屏幕上跳出来的数字，中间隔了多少层抽象，我常常懒得追。真正让我着迷的是另一件事：一段数学公式，怎么变成几万行 `always` 块，再变成示波器上一串干净的波形，最后真的从天线发出去。

这就是我给自己定下的方向——**FPGA / 数字基带开发**。

## 我每天面对的是什么

坦白讲，这行不浪漫。绝大多数时间我坐在实验室或工位上，桌面上摊开的是电脑、开发板、示波器，偶尔再加一台频谱仪。调试基本都在公司内部实验室完成，极少需要出外场——没有风吹日晒的基站巡检，也没有背着设备爬铁塔。

听起来闷，但我正好喜欢这种"所有变量都能控制住"的工作方式。

一天的循环大概是：改逻辑 → 跑仿真 → 综合实现 → 下板 → 抓波形 → 回退再改。循环很短，反馈很硬，错了就是错了，没有中间地带。

## 具体在做的事

用 Verilog 把通信链路上的一段段算法落成硬件：

- **调制解调**：发送端的星座映射、脉冲成形，接收端的载波恢复、定时恢复
- **滤波**：CIC、半带、FIR 的级联与位宽规划——难点常常不在算法，而在定点精度
- **信道编码**：卷积码、LDPC、Polar，编码器和译码器的吞吐与延迟都是硬指标
- **同步**：帧同步、符号同步、频偏估计，链路通不通，往往就卡在这一步
- **MIMO 基带链路**：多天线通道对齐、信道估计、预编码与检测

应用场景上，接触的是 5G/NR 基带、卫星通信、雷达数字前端这一类——共同点是带宽高、实时性要求死、算法还带点数学门槛。

落到工程上，绕不开三件事：**写时序约束、做仿真验证、上板调试**。前两件决定它理论上对不对，第三件决定它实际上能不能跑。三者缺一，都交付不了。

## 必学的四样

如果只让我列四条，就是这些：

1. **Verilog HDL**——注意，不是 VHDL。VHDL 在部分军工、航天项目里还有存量，但招聘市场和开源生态基本已经倒向 Verilog / SystemVerilog。学的时候要盯着"可综合子集"：哪些写法综合出来是寄存器，哪些会意外生成锁存器。
2. **Vivado / Quartus**——Xilinx（AMD）和 Altera（Intel）两家工具链各会一点最稳。综合、实现、看时序报告、用 ILA 抓波形，这些是每天的动作。
3. **时序分析**——setup/hold、时钟域、skew 与 jitter、false path 与 multicycle。这是我目前觉得最难、也最值钱的一块：功能全对的逻辑，时序不收敛就是不能交付。
4. **同步与异步设计**——跨时钟域、亚稳态、两级触发器同步、异步 FIFO、握手协议。面试必问，工程上必踩。

## 学校那四门课，别糊过去

- **信号与系统**：卷积、傅里叶、采样定理，是后面所有东西的语言
- **数字信号处理**：滤波器设计、FFT、多速率处理，直接对应你写的每一个模块
- **通信原理**：调制、编码、信道模型，决定你知不知道自己到底在实现什么
- **数字电路**：组合/时序逻辑、状态机、建立保持时间，是 Verilog 的物理底座

这四门当年觉得抽象，现在回头看，抽象的部分恰恰是把硬件细节挡在外面的那层保护。缺了它，就只剩背代码。

## 加分项

- **MATLAB 做算法定点化**：浮点仿真 → 定点仿真 → 位宽规划 → 和 RTL 比对，这条链能省掉大量返工
- **C 语言**：写测试激励、上位机交互、软硬协同
- **AXI 总线**：Zynq / SoC 上 PS 与 PL 的沟通全靠它，不懂 AXI 就只能做纯 FPGA
- **DDR**：带宽一上来就必须外挂存储，MIG、突发长度、bank 管理都得碰
- **高速接口**：SerDes、JESD204B、PCIe、以太网，基带和射频之间的那条线

## 目标岗位

三个方向，其实是一家人的三个工位：

- **FPGA 开发**：把算法变成能跑的硬件
- **基带数字开发**：更偏链路与系统，和算法工程师对接
- **数字验证**：写 testbench、做覆盖率、形式验证，保证前两位不翻车

我目前的打算是把前两条当主线，验证当保底——毕竟在任何一家做通信设备的公司里，验证岗的需求量都不小。

---

写下来才发现，这条路的核心不是"学多少工具"，而是能不能忍受长时间的"不通"。链路不通的时候，示波器上什么线索都不给，只能一层层往回剥。剥开的那一刻，是这行给我的全部回报。
